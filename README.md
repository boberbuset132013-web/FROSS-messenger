# FROSS Messenger

FROSS Messenger — мессенджер на HTML/CSS/JS, Cloudflare Workers и Cloudflare D1.

## Возможности V2
- Регистрация с четырьмя шагами: имя, профиль, аватар, оформление и подтверждение правил тестовой версии.
- Вход и выход, смена пароля, удаление аккаунта.
- Личные чаты и групповые чаты.
- Поиск пользователей по имени и отображаемому имени.
- Профиль: отображаемое имя, описание, email и аватар.
- Настройки интерфейса: тема, цвет акцента, размер шрифта, оформление сообщений и фона, время и плотность чата.
- История сообщений сохраняется в D1; интерфейс обновляет её периодическими запросами раз в 2,5 секунды.

## Структура проекта
- `worker.js` — API, авторизация и работа с D1.
- `public/index.html` — интерфейс сайта.
- `migrations/0001_init.sql` — исходная схема первой версии.
- `migrations/0002_profiles_chats.sql` — схема V2.
- `UPGRADE_D1_V2.sql` — одноразовый SQL для обновления уже работающей базы, включая фиксацию истории миграций.
- `prototype.html` — исходный HTML-прототип.

## Важно: обновление уже существующей базы
У существующего экземпляра D1 схема `0001_init.sql` была создана вручную через D1 Console. Поэтому Wrangler не видел запись о применении этой миграции. **Не запускай просто `wrangler d1 migrations apply` на этой базе до заполнения таблицы `d1_migrations`** — Wrangler мог бы попытаться выполнить исходную миграцию повторно.

Порядок обновления:
1. Сделай резервную копию D1 (например, через Time Travel / Export в Cloudflare).
2. Открой D1 `fross-messenger-db` → Console.
3. Открой в GitHub файл `UPGRADE_D1_V2.sql`, скопируй его целиком в Console и выполни один раз. Он добавляет профильные поля к существующим пользователям, создаёт `chats` и `chat_members`, а затем отмечает миграции `0001_init.sql` и `0002_profiles_chats.sql` как уже применённые в `d1_migrations`.
4. Проверь Worker endpoint `/api/health`. В ответе должны быть таблицы `users`, `sessions`, `messages`, `chats`, `chat_members` и `tablesReady: true`.
5. Только после успешной миграции переключи production на ветку `feature/messenger-v2` (или смержи её в `main`). Workers Builds опубликует новую версию.

**Не запускай UPGRADE_D1_V2.sql повторно:** команды `ALTER TABLE ... ADD COLUMN` выполняются только один раз. Скрипт сохраняет существующие строки пользователей и сообщений; он не удаляет эти данные.

## Новая база с нуля
Для пустой базы можно выполнить `schema.sql` целиком через D1 Console. Это полная схема V2. После ручного выполнения можно создать baseline таблицы миграций отдельно, если планируется использовать Wrangler migrations.

## Cloudflare / Wrangler
- Worker: `fross-messenger`.
- D1 database: `fross-messenger-db`.
- Binding в Worker: `DB`.
- Frontend assets: `public/`.
- Конфигурация: `wrangler.toml`; Database ID уже настроен для текущей D1.

Команда публикации:
```sh
npm run deploy
```

После базовой фиксации истории миграций новые SQL-миграции можно добавлять в `migrations/` и применять командой:
```sh
npm run d1:migrate:prod
```

## Текущие ограничения
- Обновление чатов пока идёт polling-запросами, не WebSocket.
- Голосовые и видеозвонки, вложения/облачное файловое хранилище, push-уведомления и сквозное шифрование пока не входят в V2.
- Перед публичным запуском нужны rate limiting регистрации/входа, антиспам, восстановление аккаунта, политика хранения/удаления данных и дополнительный security review.
